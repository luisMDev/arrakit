# File ownership per feature module

Each feature module edits only the files and directories it owns, so modules can be built in
parallel without merge conflicts. Every procedure, table, route, screen, locale file and email
template already exists, so **no module needs to edit a shared file**.

New files inside an owned directory are fine (for example `apps/api/src/billing/billing-view.ts`).
Tests live next to the code they test and belong to the same owner.

## Shared files (nobody edits them during feature work)

| File                                                                                                | Why it never needs an edit                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/db/src/schema/index.ts` (+ per-domain schema files)                                       | Every table of every spec is declared and migrated (`drizzle/0000_init.sql`, `0001_*`)                                                                                                                                |
| `packages/db/src/open-data.ts`, `packages/db/src/organization/index.ts`, `packages/db/src/index.ts` | Compose the per-domain `data/*` and `organization/*` modules; signatures change inside those modules. Export new public types from your module file and import them by path if `index.ts` lacks them, or ask platform |
| `packages/contract/src/index.ts`, `packages/contract/src/common.ts`                                 | Compose module contracts (`organizations` = onboarding + organizations, `billing` = billing + top-up)                                                                                                                 |
| `apps/api/src/router.ts`, `apps/api/src/app.ts`                                                     | Compose routers and mount every route file; `app.ts` also holds the `/api/rpc/*` CSRF (trusted Origin) middleware                                                                                                     |
| `apps/api/src/orpc/{base,context}.ts`, `apps/api/src/deps.ts`                                       | Builders and middlewares every router uses (`reportErrors` maps every `DomainError` from `packages/db` to an oRPC error)                                                                                              |
| `packages/auth/src/{auth,deps,index}.ts`, `packages/auth/src/client.ts`                             | Wire the per-concern auth files into `betterAuth()`                                                                                                                                                                   |
| `packages/emails/src/index.ts`                                                                      | Every template is already exported                                                                                                                                                                                    |
| `apps/web/src/routeTree.gen.ts`                                                                     | Generated; every route file already exists                                                                                                                                                                            |
| `apps/web/src/components/ui/`                                                                       | shadcn components as shipped                                                                                                                                                                                          |
| `pnpm-lock.yaml`, every `package.json`                                                              | All dependencies are installed (see AGENTS.md)                                                                                                                                                                        |

If a module truly needs a shared file changed, it stops and reports it instead of editing.

## Cross-module contact points

- **Org deletion** (organizations-members) calls `deps.stripe.endNow()` (billing gateway interface)
  and `queueStoragePurge()` from `apps/api/src/workers/storage-purge.ts` (platform).
- **Invites** (organizations-members) send the magic link through `deps.auth.api.signInMagicLink`;
  the MailMember choice lives in `packages/auth/src/magic-link.ts` (auth-onboarding) and uses
  `memberEmail` (organizations-members) and `invitationFor` (organizations-members).
- **Member removal / org deletion** call `revokeGrants()` (organizations-members), which MCP
  (platform) relies on.
- **Settings > Billing** (billing) embeds the usage cards and Add credits dialog from
  `apps/web/src/components/usage/` (usage-credits).
- **`me.get`** is implemented in `apps/api/src/routers/account.ts` (organizations-members); the
  guards (auth-onboarding, shell-landing) only read it.
- **Workers**: a module that adds a queue puts its register function in its own file under
  `apps/api/src/workers/` and asks platform to add the one line in `workers/index.ts`.
